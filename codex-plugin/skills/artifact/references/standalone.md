# Surface: standalone — self-contained interactive documents

Author a **self-contained artifact** (report, analysis, review, dashboard, showcase) and deploy it to vitrinka. There is **no build step**: pushing the file IS the deployment, and every re-push updates the same URL.
pin: e2e/artifact-refresh.spec.ts#an ordinary reload after a push shows the new revision; unchanged assets stay cacheable

Capturing UI work in progress belongs to the **publish** skill; delegation to `vitrinka-publisher` per Shared core in `../SKILL.md`.

## Workflow

1. **Scaffold**: `vitrinka board artifact init --slug <slug> --kind <report|analysis> --title "<Human title>"` → `.vitrinka/artifacts/<slug>/` with an editable `index.html` (import map: `react`, `htm`, `kit-3`, `zipstore-1`; the load-bearing theme contract) and a `doc.json` skeleton that renders through kit-3's `<Doc>`. From this session's screenshot set instead: `vitrinka board artifact-from-set --slug <slug> [--select 1,3-5]`.
2. **Fill** — data-first by default: author only `doc.json`, never open `index.html`; the push validates every block server-side and the kit owns every visual decision. An architecture diagram is a first-class block: `{kind:"diagram", title, caption?, …}` carrying the exact board diagram-card semantics (lanes/groups/nodes/edges, no coordinates — vocabulary: `diagram.md`, this directory), ≤12 per doc; the server lays it out and scores it at push, and the diagram paints LIVE through the one React painter — there are no stored SVG stamps; never author `geo` or `render` (a stale `render` copied from an older doc is dropped at push).
   pin: e2e/render-audit.spec.ts#the pushed document paints its diagram live, loads figures eagerly and keeps section edges aligned
   Iterate from your AUTHORED doc.json, never by re-pushing the stored stamped bytes (stamped geo/metrics count against the 2 MiB authored cap). Compose components only when the document needs behavior or a block that doesn't exist: edit `index.html`, replacing or surrounding `<Doc>` with kit-3 components in htm.
   **Layout and nesting are blocks, not markup**: `{kind:"columns", ratio?, cols:[{blocks}]}` is the ONE horizontal grammar (2–3 columns, collapses when narrow — a score strip beside its verdict, a meter beside its chart; never prose); `{kind:"ref", card|page|section, mode?: link|preview|embed}` points at another document card — `page` names a sibling page slug inside the same push; the server resolves it and stamps `target` (never author `target`) — or, with `section`, at a section of THIS document. A `timeline` takes `axis: spine|time` (spine default; `time` needs parseable `when` dates and falls back to spine).
   **Links are first-class — a claim without a reachable proof is half-written.** Every section is an anchor: author `id` (`^[a-z0-9][a-z0-9-]{0,63}$`) or let the push derive it from the label (`"02 · Pricing"` → `02-pricing`, collisions `-2`, `-3` in document order); `/a/<card>#<id>` deep-links into the document and `{kind:"ref", section:"<id>", label?}` cross-references it in place (a missing id rejects the push naming the ids that exist). A table cell carries a link as `{v, href, tone?}` and renders inline markup like prose (`**bold**`, `` `code` ``, `[text](url)`); a target anywhere is `https://…`, `mailto:`, `#<section-id>`, `/path` or a source alias. **Cite code without typing URLs**: declare each repository once in `meta.sources` (`{"pwf": {"repo": "ByADF/pwf-service", "ref": "byadf/feat/forge-pricing"}}`) and write `pwf:config/application.yaml#L3-L9` as any link target — the push expands it to the canonical GitHub URL and, when the deployment holds a GitHub credential, verifies the path exists at that ref (a miss fails the push naming the link; without a credential the envelope warns that links went unverified). An undeclared alias is an error, which is also what keeps stray schemes out.
   pin: e2e/render-audit.spec.ts#links are first-class: section anchors, in-document refs, cell links and expanded source aliases
   **Pictures are compositions, numbers are comparisons, one document serves every reader.** Several screens of one feature are ONE `gallery` block (`layout: bento|carousel|masonry|grid`, `items` like figures, `span:"large"` picks the bento hero, `tall` for phone shots) — never a stack of full-width figures: bento for 3–6, carousel for many or a phone set, masonry when nothing may crop. A before → after measurement is a `chart` with `viz:"compare"` and a declared `better: lower|higher` (the change chip's tone follows it — still never the sign); when one chart mixes metrics, an item's own `unit` overrides `data.unit` for its row and each unit gets its own bar scale. Tag a block `audience: [public|technical|internal]` when only those readers need it (untagged = everyone): the viewer's Audience switch and every export (PDF, HTML, Email, Word) cut by it, so the PR provenance and the QA notes ride the same document as the customer copy. A table row takes the same tag as `{cells: [...], audience: [...]}` beside plain rows — one table, never a split one. The hero is meta — `accent` (the title phrase the display type leans into), `intro` (the lede), `chips`, `accentColor` — and `==text==` marks the one phrase a reader must not miss. Shapes: `docs element:gallery`, `element:chart`, `artifact:docjson`.
   pin: internal/ingest/doccard_test.go#TestBuildDocElementReleaseVocabulary
3. **Look up, don't recall.** Every shape table, prop list, chart form and component palette lives in the deploy's own docs layer — the `docs` MCP tool, or `vitrinka docs <topic>` (`vitrinka docs` for the index). Topics: `docjson` (the block vocabulary), `charts` (the viz language), `scaffold`, `theme`, `shelf` (the vendored runtime), `design`, `gotchas`, plus one per kit component and one per element kind (`element:chart`, `element:table`, …). Validation is **strict canonical**: fields the contract doesn't name reject the push (no silent pruning).
   pin: e2e/artifact-theme.spec.ts#a doc.json that breaks the contract is rejected at push with the exact message
4. **Push**: `vitrinka board push --root .vitrinka/artifacts/<slug> --title "<Human title>"`.
5. **Verify, then iterate**: read the push's diagnostics AND `render.png` beside the artifact. A render error (`render.console`, blank `render.root`) is unfinished work even though the push succeeded: fix and re-push (same key → same URL). doc.json mistakes reject with exact machine-readable diagnostics; mechanical typos are autofixed at preflight (`fixed:` lines, `--no-fix` disables). Diagnostics carry `see` pointers into the docs layer — follow them. Diagram blocks report through the same envelope: composition findings arrive `blocks[i]`-prefixed with verified `fixes` (measured deltas) — apply at most one diagnosed fix per round, ≤2 rounds, report leftovers truthfully (the quality loop, `diagram.md`).
   pin: internal/docspec/autofix_test.go#TestAutofixEnumNearMisses

## Laws that stay in force while composing

- **Compose kit blocks first; never re-implement a kit block.** Bespoke markup only for what no block expresses.
- **The theme contract in `<head>` is load-bearing**: bespoke markup styles with the tokens (`--bg/--surface/--ink/--muted/--rule/--accent`; Tailwind arbitrary values read them: `text-[var(--muted)]`) — never hardcode a palette, never delete the block.
  pin: e2e/artifact-theme.spec.ts#semantic artifact themes natively in both directions and decodes entities
- **htm renders HTML entities literally** — write `→`, `·`, `—`, never `&rarr;` (preflight decodes them outside code/html blocks).
  pin: internal/docspec/autofix_test.go#TestAutofixDecodesEntitiesExceptCodeAndHTML
- **Tone is explicit meaning, never sign-inference.** A number only colors when you state its meaning (`tone: good|warn|bad|neutral`) — +79% frame time is *bad* despite the plus sign.
  pin: e2e/artifact-theme.spec.ts#presentation blocks: top-level rhythm, explicit tones, charts, meter, compare
- **A finding must carry its proof**: `status`, `cause`, `summary`, `evidence` — the exact log, file, query or check.
- **A repo `DESIGN.md` is the style authority** (tokens + prose brief; discovered and sent with every artifact push — `design: <path>` in the narration; resolution is server-side: repo ▸ workspace DESIGN ▸ kit presets; explicit `meta.direction`/`meta.accentColor` always win). Pick `meta.direction` deliberately — `editorial · dossier · terminal · gallery · release` are five distinct identities (`release`: release notes as a product page — display title, KPI tiles, chapters, features under a chip).
  pin: e2e/artifact-design.spec.ts#stamped DESIGN tokens apply as defaults: direction, density, accent
  pin: e2e/artifact-design.spec.ts#explicit doc.json meta beats the DESIGN layer
- **Never drive Playwright/Chrome to "check it renders"** — the viewer is login-gated and the push's own render already saw the page. Where no screenshot came back, fall back to a token curl (Bearer header via stdin, never argv). **The link goes in your final summary, always.**
- The artifact appears on its project's home under the **Artifacts** tab (and on the project's artifacts board), labeled by title — pick a real `--title`. The project slug comes from the committed repo-root `vitrinka.config.json`; `--project` only overrides.
  pin: e2e/artifact-theme.spec.ts#artifacts list under the project's Artifacts tab, apart from the journey versions
- **A semantic push also mints/updates a `doc` card** on the project's artifacts board (keyed by project/branch/slug, versioned — the ⌥ fan recovers old pushes) and the response carries its solo `element:` URL (`/a/<card>`) beside the set URL. Hand back what the push prints (field names: `../../publish/references/wire-fields.md`). Blocks with no canonical element yet skip the card with an advisory diagnostic — the set + raw view stay authoritative for those.
  pin: e2e/render-audit.spec.ts#a fully canonical document mints its doc card and the solo view paints every block, nested diagram included
- **Multi-page artifacts are a `pages/` directory, one push**: `pages/<slug>.json` beside `doc.json` — each a FULL doc.json (meta + blocks, same validator, same diagram stamping, slug = lowercase/digits/hyphens ≤64). The root and any page point at a sibling with `{kind:"ref", page:"<slug>", mode?: link|preview|embed}`; `vitrinka board push` sends the whole directory, preflights every page, and refuses a `page` with no file — the server rejects the same, naming the path (`pages/rizika.json:blocks[2].page`). One push mints the root AND one `doc` card per page on the artifacts board (keyed by set + slug so a re-push updates the same cards), rewrites page refs into card refs, stamps each ref's `target` and draws the `ref` wires — `arrange {mode:"graph"}` lays the tree out and the solo view's outline rail walks it. The response adds `pages: [{slug, url, cardId}]` (`--json` too); the CLI prints one `page <slug>: <url>` line each. Cycles are fine. Hand back the root URL plus the page lines.
  pin: internal/web/push_pages_test.go#TestPushPages_MintsCardsRewritesRefsAndWires

Everything else — block shapes, meta fields, chart data forms, the runtime shelf, sandbox and offline gotchas — is `vitrinka docs`, not this file.
